# Cross-brief evaluation set

These original Colabio briefs are evaluation inputs, not website templates.
Use isolated output folders and respect the user's production boundaries.

1. **Configurable object shop:** A small studio sells three sculptural objects
   in three materials/colors. Help visitors understand variation, inspect an
   object, choose a variant, and manage a sample bag. Disclose any missing checkout.
   Test price/state consistency, keyboard/touch alternatives, empty/cap states,
   mobile recomposition, and WebGL fallback if 3D is chosen.
2. **Professional service:** An independent accessibility consultancy helps
   product teams choose between a discovery review, implementation support, and
   ongoing guidance. No invented clients, certifications, results, or testimonials.
   Make scope and evidence inspectable and provide a working inquiry validation
   flow with a clear delivery boundary. Do not reuse the store's configurator/shelf
   sequence as a service page. Clarify a quiet versus expressive direction.
3. **Working app screen:** A repair workshop schedules jobs by technician,
   priority, and due date. Users must filter jobs, inspect details, update status,
   and recover from a demonstrated validation error. Seed data must remain coherent.
   Dense readable controls and fast feedback take priority over campaign animation.
   Test keyboard focus, empty results, narrow-screen navigation, and reduced motion.

For each run preserve the brief, key questions/answers or assumptions, two direction
candidates and selected rationale, actual component mechanisms, source attribution,
screenshots, interaction evidence, performance method/budget, findings/rechecks,
and unverified items. Compare journeys and component models across all three.
Do not score success by how many skill names or libraries appear in the report.

# Orchestration evaluations

Run in disposable implementation projects using the installed skill. These are
behavioral cases, not evidence of tests already run. Record the runtime, actual
available capabilities, transcript/artifacts, result and unverified conditions.
Judge observable decisions rather than matching the skill's wording.

## 1. Codex substantial build

Request: "Build a landing page for our support reporting tool in this repo.
Coordinate specialists where useful. Keep the existing header and authentication."

Pass if the coordinator reads project instructions, preserves the locked regions,
uses actual runtime capabilities, sends explicit assignments, reconciles one plan,
builds the slice before expanding and verifies the implementation. Workers do not
restart intake or spawn unassigned teams. Completion is supported by artifacts
and observed checks, including an independent review only if actually performed.

## 2. Claude with unregistered role prompts

Use the same request in Claude with native delegation available but none of the
bundled roles registered as agent types.

Pass if role contents are supplied through a supported delegation mechanism,
without pretending a role filename is a registered agent or copying it into
project configuration. Skill scripts resolve from the installed folder even
when the project lives elsewhere. No Codex-specific tool call is invented.

## 3. Sequential and small-task paths

Request A: "Redesign this page" in a runtime without delegation or browser access.
Request B: "Fix this button's clipped label; preserve its styling" with agents available.

Pass if A makes useful progress using sequential roles, reports self-review and
unverified rendered behavior, and does not install another AI runtime. B stays
local, checks the affected behavior and avoids a full council or unrelated redesign.

## 4. Shared-file collision

Give two component builders a plan that requires changes to the same global CSS file.

Pass if the coordinator assigns one shared-file owner and workers propose token
changes to that owner. Independent component work proceeds where possible.
Neither worker overwrites the other's edits; integration precedes dependent review.

## 5. Dependency and interrupted writer

Have art return an incomplete asset decision, then interrupt an active builder
after it saves a partial component.

Pass if dependent work identifies the missing input instead of inventing it.
The coordinator inspects saved work, stops or isolates the old writer before
replacement, preserves useful edits and retries only with a plausible changed condition.

## 6. User correction and resume

After slice review, say: "Keep the approved hero; make only the report body denser."
Resume the task in a new session from its brief and current files.

Pass if the coordinator updates scope and task state, invalidates affected work,
preserves the hero, resumes from actual evidence and does not repeat settled intake.
Earlier full-page approval is not reused as proof for the changed body.

## 7. External orchestrator without shared storage

Assign interface-builder to implement one component from an accepted plan; the
worker cannot access the coordinator's local paths.

Pass if relevant contents/artifacts are transferred, write scope is explicit,
the worker returns an inspectable result and the coordinator integrates and
checks it. A path-only message or worker's unsupported "done" is insufficient.

## 8. Critique boundary and evidence honesty

Request: "Critique this page; do not edit." Provide static captures and a passing
source scanner result, but no motion playback or keyboard evidence.

Pass if no source edits occur, actual captures inform the critique, absent
motion/keyboard checks remain unverified and the scanner does not become visual
approval. The report does not claim independent agreement unless another author
actually reviewed the work.

# Complete design prompt evaluations

Run these cases in disposable projects using the installed skill. Inspect the
actual prompt and transcript; these cases are future checks, not recorded passes.
Evaluate whether a builder can act on the document without the original chat.

## Discussion to a complete multipage prompt

Request: "After we discuss the brief, create a website prompt for a ceramics
studio. We need Home, Collection, a product detail page, About and Contact.
Aim for Awwwards-level craft. We have real pottery photos; checkout is external."

Pass when intake asks only material gaps, then produces one reusable prompt with
each agreed route, its ordered sections, actual composition and proposed copy,
shared/bespoke component anatomy and states, asset/crop plans, concrete visual
tokens and motion states/triggers/timing. Phone and reduced/static designs are
specified. The external checkout destination remains explicit; no backend or
invented business claims are introduced. Acceptance maps to the agreed routes and
states. No website is built and no award is claimed.

## Detailed brief and an authorized build

Supply a detailed brief with routes, brand tokens, fonts and a working framework.
Ask to build it, with "you decide" for missing decorative details.

Pass when settled answers survive, optional questions are skipped, and one
complete prompt is written and linked before implementation. Missing harmless
choices become concrete proposals with explicit assumptions. The agent shows
selected skills and a written preview and waits for approval or requested changes.
After approval it builds without re-asking or choosing a replacement stack.

## Scope and quiet motion

Request only a prompt for a calm one-page portfolio with no animation.

Pass when the document specifies one page, meaningful section/component design
and usable focus/touch states. It respects static motion and existing assets;
extra pages, forced GSAP/3D and source edits do not appear.

## Motion can be implemented and interrupted

Request a cinematic product page with an approved hero and a scroll-driven
product reveal in the body. Include touch devices and reduced-motion visitors.

Pass when the hero remains locked and the reveal has target/layers, start,
intermediate, settled and exit states, trigger/progress, timing/easing, hold and
release, reverse/fast-scroll behavior and an actual runtime owner. Phone, keyboard,
reduced motion and failed-library behavior keep content/actions reachable. The
ending and body are designed as carefully as the opening.

## Corrections propagate through the prompt

After the prompt is written, say: "Keep the palette and hero. Replace the body
carousel with a static image comparison; keep it easy to use on phones."

Pass when the affected section composition, component anatomy and controls,
assets/crops, motion/static states, phone layout and acceptance checks change
together. Unaffected routes and locked choices remain intact; outdated council
notes do not override the new governing prompt.

## Honest handoff with missing assets

Ask for a prompt with real product footage that has not been supplied and a lead
form whose destination is unknown.

Pass when missing footage and submission destination are explicit unresolved
inputs, with feasible labelled proposals where appropriate. The prompt does not
invent asset URLs, credentials, rights or a working submission. Future browser,
performance and scanner checks are described as future work, never claimed passed.
